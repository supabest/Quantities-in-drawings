# 227户型平面算量 — 面积口径对账调查纪要

> **日期**: 2026-09-19 ~ 2026-10-02  
> **触发问题**: 三维建模(base_extract)围合几何净面积 163.9㎡ vs P01(平面布置图)标注 188.2㎡，缺口 −12.9%，最大单项"主人套房" 差 9㎡  
> **最终结论**: 缺口不是漏切/围合错误，而是面积口径不同(净 vs 含墙/轴线)；进一步发现 **P01 标注(=p11)是离群参考值, 工程量清单(BOQ)的楼面完成面积才是算量对账的权威基准**

---

## 一、排查过程

### 1.1 最初假设："主人套房被切走 9㎡"

前序建模产出 163.9㎡(LOOSE 围合, 墙+FIN 全部方向+门窗封开+桥接)，对比 P01 标注 188.2㎡。最大缺口出现在"主人衣帽间+主人卧室"合并项：几何 17.32㎡ vs 标注 26.1㎡，差 8.8㎡。

**排查动作**:
- `_diag_master.py`: scipy.ndimage 连通域着色 + 放大绘图 → 主人卧室+衣帽间在同一连通域 #34=17.15㎡, 轮廓完整无泄漏, bbox 3.24×5.92m=19.2㎡（填满也不到 26.1）
- 对照实验: `strict_enc=True`(仅真墙, 去 FIN) 反而错误合并中厨/生活阳台 → 确认 LOOSE 是正确围合
- `_diag_suite.py`: 膨胀 2px 检测是否触及 border → 无房间触边, 排除漏口
- **结论**: 不是被切走、不是泄漏, 每间面积合理, 高填充率, 规整轮廓

### 1.2 方案 A 落地："几何为真值 + P01 作参考列 + 复核清单"

用户确认: 围合几何=模型唯一真值, P01 面积只作 Pset_Room 参考, 偏差>15%挂 FLAG。

代码产出:
- `base_extract.build()` → `r["p11"] = p11_ref(names)` (内置 P11_NET 表)
- `ifc_export.Pset_Room` 加 `P11NetArea_m2`、`AreaVariance_pct`
- `run_model` → `area_reconciliation.md` 复核清单

跑通结果: 匹配13间, 几何 150.7 vs P01 188.2 = **−19.9%**（比含电梯厅的−12.9%更准），10间偏差>15%。

### 1.3 关键实验："夹墙最外线定界" → 发现 p11 = 含墙口径

带着"是不是口径不同"的假设，从 DXF 提取所有尺寸标注(534 DIMENSION)，尝试对 flagged 小房间做交叉验证。

**踩坑**: 
- DXF ALIGNED 标注(对齐型)的 defpoint/defpoint3 不沿 H/V, 用其分类方向不可靠
- `get_measurement()` 返回真值可信但无方向
- 房间净尺寸画在外围尺寸链(分段累加)而非单条, 房内只剩洁具标注

**正解: 夹墙最外线定界** (`base_extract.gross_area()`):

### 1.4 真异常收敛 + 衣帽间定位

以 p11 vs 含墙×1.02 为"真异常"判据, flagged 从 10 间收敛至 2 间:
1. **主人套房(衣帽间+卧室)**: 26.1 > 含墙 23.6 → 缺口全在衣帽间(rev-33净~6㎡ vs P01 11.2㎡)
2. **收纳间**: 3.3 > 含墙 3.2 → 临界+0.1㎡, 可忽略

## 三、最终口径体系

```
┌─────────────────────────────────────────────────┐
│  面积口径层级 (227户型, 2026-10 定稿)              │
├─────────────────────────────────────────────────┤
│  净面积(NetArea)   ← 墙内面, 装饰面层算量用        │
│  含墙外包(GrossArea) ← 墙外面最外线, 上界校验       │
│  清单BOQ楼面面积    ← 算量对账的【权威基准】         │
│  P01标注面积       ← 已降为参考(实为含墙口径离群值)   │
└─────────────────────────────────────────────────┘
```

判据:
- BOQ ∈ [净, 含墙×1.05] → 口径一致(非错误)
- BOQ > 含墙×1.05 → 标记"查(飘窗/围合)"
- BOQ < 净×0.95 → 标记"查(BOQ偏小)"
- 含墙不可定界(开放区) → 按 BOQ vs 净比较, 以 BOQ 为准

## 五、工作流教训

1. **口径先行**: 面积对账的第一步不是调围合, 而是确认各方(标注/几何/清单)各自的面积定义(净 vs 含墙 vs 轴线)。
2. **不要盲信"标注=净面积"**: P01 的 "NN.N s.m." 实为含墙/轴线口径, 建筑师通常标含墙面积。
3. **BOQ 是最终算量目标, 不是"参考答案"而是"真实需求"**: 对账基准应该是清单(因为算的就是清单里的量), 而非图纸标注。
4. **分组比对需去重**: 合并房间(客厅+餐厅+玄关)共享一个 comp_id, 按名字取会重复累加。
5. **开放区无四面墙 → gross=None**: 不能强求含墙定界, 只能按 BOQ 为准。
6. **CAD 尺寸标注不可按 defpoint 分类方向**: 对齐型标注(ALIGNED)占多数, 其 defpoint 不沿 H/V。
7. **排查从最大异常开始, 但结论要泛化**: 从主人套房的 9㎡ 缺口入手, 最终得出"全部小房间都因口径而偏"的普适结论。
